# Options

Reader: an agent holding a requirement that leaves more than one way to meet it.

## When

- A record can be met by more than one design, and the work issue has to pick one.
- The first idea is the only one on the table.
- Someone asks why the chosen way was chosen.

## Steps

1. Restate the requirement the options must meet; an option that fails a must is not an option.
2. Write at least three options, including doing nothing and the smallest change that could work.
3. Give each option one line on what it is and one line on what it costs, measured on the tree
   where it can be.
4. Drop an option only for a stated reason: it fails a must, or it is the same as another.
5. Name the criteria the choice turns on, taken from the records' priorities, not invented here.
6. Hand the options and the criteria to the decision skill, which makes and records the choice.
7. Write the options not picked, each with its reason, where the choice is recorded.

## Where it goes in SE

The options and criteria go to the decision skill, whose note owns the choice. The picked option
becomes the work issue's Approach section, which names the options not picked and why.

## Source

Karl Ulrich and Steven Eppinger, "Product Design and Development", McGraw-Hill, 1995: generate a
set of concepts before selecting one, and keep the reasons the others were dropped.
